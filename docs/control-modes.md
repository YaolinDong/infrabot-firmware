# 机械臂分层模式与使能

## MCU 控制器状态和 UDP 控制权

MCU 是整机控制器。有效运动或配置写请求会把控制权租约绑定到一个
UDP 源 IP/端口；机械臂使能或运动期间，其他来源会被拒绝。全部失能后
才允许新的来源接管。`DISABLE` 和 `STOP` 始终作为安全操作接受。
遥测注册也服从同一租约：控制期间其他来源不能改写唯一的遥测目的端点，
避免第二个 PC 让当前控制器失去反馈；控制者本机（同一 IP）可以重新注册，控制者 500 ms
无消息后其他来源也可以接管（见“受控停止”）。

报文定义在 `protocol/infrabot/protocol.h`（见“协议头文件”）。遥测为 DMTL v3
（见“遥测 v3”），前 180 字节与 v2 相同：`status` 字节（v2 的 `reserved[0]`）bit0 表示使能、bit1 表示
零点有效，bit2..7 表示控制器状态：`0 BOOTING`、`1 PRECHECK`、
`2 PROFILE_REQUIRED`、`3 DISABLED`、`4 ENABLING`、`5 IDLE_HOLD`、
`6 RT_JOINT`、`7 RT_CARTESIAN`、`8 NRT_JOINT`、`9 NRT_CARTESIAN`、
`10 STOPPING`、`11 FAULT`、`12 RECOVERY`、`13 ESTOP`。

参考 Flexiv 的 IDLE、显式 SwitchMode、RT 连续指令及 NRT 内部轨迹生成概念，
按本机械臂硬件拆成两层。

```text
电机配置层（先全部失能，再选择并应用）
├─ J1–J7 MIT
└─ J1–J7 位置速度
   J8 在两种配置下均为力位混合

执行层（配置成功后才能使能；使能只进入 IDLE 保持）
├─ IDLE                 不接受运动目标，已使能时保持当前位置
├─ RT_JOINT / servej    PC 1 kHz 关节目标，MCU 1 kHz CAN
├─ RT_CARTESIAN / servep    PC 1 kHz 笛卡尔目标，MCU 1 kHz IK + CAN
├─ NRT_JOINT / movej    PC 100 Hz 保活，MCU 1 kHz 插值与实际到位判断
└─ NRT_CARTESIAN / movep    PC 100 Hz 阻塞目标，MCU 1 kHz IK + 到位判断
```

## Qt 使用顺序

1. 更新 MCU 固件，并重新编译配套 `udp_control_gui`。连接后确认模式区有实际状态。
2. 在“① 电机模式”选择 MIT 或位置速度，点击“应用电机模式（失能时）”。
3. 点击“② 全部使能”（机械臂+夹爪），或只点“使能机械臂”（见下方“机械臂与夹爪分开使能”）；
   MCU 进入 IDLE 保持当前位置，不会自动回零、进入 RT 或提交 movej。
4. 在执行模式下拉框选择 RT Joint 或 NRT Joint，点击“应用控制模式”。
   仅改变下拉框不发送命令；以“MCU 实际”显示为准。
5. RT Joint 下拖动滑条更新目标；NRT Joint 下滑条只编辑草稿，点击“执行 movej”
   才提交新动作。到位且稳定、MCU 返回 DONE 后才允许下一条。
6. 静止后可点击“返回 IDLE（保持）”。RT 与 NRT 之间必须先经过 IDLE。
   更换 MIT/位置速度必须再全部失能。全部失能回到 IDLE；断线超时做受控停止，刹停后在 IDLE 一直保持使能
   （见“受控停止”）。两者都不自动恢复运动；受控停止后点“恢复”回到原来的模式，从停下的位置继续。

IDLE 与“失能”不是一回事：IDLE 可以已使能并按 1 kHz 保持；失能会撤去输出。
IDLE 和 NRT 准备期使用 100 Hz 无目标心跳，不再借用旧 RT 目标流。
NRT 完成后的保持会话可释放到 IDLE；运行/等待到位期间拒绝切换，需等待或显式取消/失能。
切换要求机械臂 J1–J7 已使能、反馈不超过 50 ms、无故障、速度绝对值不超过 0.05 rad/s（夹爪不检查，
可以失能或不在；模式切换也不改变夹爪的指令）。
与 Flexiv 的自动停车切换不同，模式切换在运动中返回 BUSY，**不会自动规划减速停车**；要停下来用 STOP
（DMCP v3 命令 5），MCU 受控停止后回到 IDLE 保持（见“受控停止”）。

使能前后清空旧实时队列与速度/力矩目标，并在分阶段使能前请求新反馈、使用当前角度保持。
Qt 同步滑条显示时阻断信号，不把 UI 更新当成运动命令；进入 RT/NRT 也从实际位置开始。
位置保持不是“物理上保证完全不动”：载荷、无重力补偿、增益、驱动内部行为仍须实机验证。
先支撑机械臂、准备急停再验证。失能不是安全制动。

## 模式协议

控制器发现使用 DMIF/DMIO：PC 发送 16 字节 DMIF 信息请求，MCU 从请求源
端口回复 DMIO，包含当前控制器状态、实际模式、配置就绪位、逐轴位置/速度/
力矩限制以及能力掩码。DMIO 只读，不能替代后续遥测状态确认。

保留现有 DMCP/DMTL 结构尺寸，新增命令：

| 命令 | 报文 | 含义 |
|---|---|---|
| 5 STOP | DMCP v3 | 受控停止：刹停并在 IDLE 保持，不失能；任何来源都可发送，重复发送无副作用（以前 v3 不接受 STOP） |
| 18 SET_ARM_MODE | DMCP v4 | 原接口；motor_index=255，mode=1 MIT / 2 位置速度；最后做参数自检，不通过时 status=6 |
| 20 SET_CONTROL_MODE | DMCP v4 | motor_index=255，mode 为下表执行模式；通过 DMAR 确认 |
| 21 HOLD_HEARTBEAT | DMCP v3 | 无目标保活；所有目标字段均忽略，不刷新 RT/已占用 DMOV 的看门狗 |
| 22 GET_HOLD_POSITION | DMCP v4 | 只读；motor_index=0..7，DMAR `value` 为该电机当前保持指令（关节坐标 mrad，int32）；未使能 status=7 |
| 23 ENABLE_ARM / 24 ENABLE_GRIPPER | DMCP v3 | 只使能机械臂 J1–J7 / 夹爪 J8；须 IDLE 且电机模式已应用；以遥测 enabled_mask 确认 |
| 25 DISABLE_ARM / 26 DISABLE_GRIPPER | DMCP v3 | 只失能机械臂 / 夹爪，另一组继续运行；与 DISABLE 一样任何来源都可发送 |
| 27 GRIPPER | DMCP v4 | 夹爪指令，任意控制模式（含 movej/movep 进行中）：motor_index=7，`target_position_mrad[7]` 位置（关节坐标，0–5940 mrad，即夹爪全行程 0–5.94 rad），`velocity_limit_mrad_s` 速度上限，`torque_ratio_milli` 力（电流上限，0–1000‰）；DMAR status 0 已执行、3 超范围、7 夹爪未使能 |

执行模式编号：0 IDLE、1 RT_JOINT、2 RT_CARTESIAN、3 NRT_JOINT、4 NRT_CARTESIAN。
DMAR `value` 返回当前实际执行模式；status=0 成功，3 参数错误，4 忙/运动未结束，
6 配置未应用或非法模式迁移，7 机械臂未全部使能/反馈过期/故障。RT/NRT Cartesian 使用 MCU
内置无动态分配 IK；不再以“接口尚未实现”拒绝笛卡尔模式。
重复设置当前模式不重置目标。笛卡尔请求必须使用对应的 pose 报文格式，否则保持原模式并返回参数错误。

### 机械臂与夹爪分开使能

电机分两组：机械臂 J1–J7、夹爪 J8。用于不带夹爪运行（工具标定、负载标定、动力学参数辨识）、更换
夹爪，或单独上下电夹爪。MCU DMIO 能力位 0x40 表示支持。

- **控制模式只需要机械臂**：RT/NRT Joint/Cartesian 的切换、movej/movep 只检查 J1–J7；夹爪可以失能，
  也可以完全不在总线上。
- **使能**（ENABLE / ENABLE_ARM / ENABLE_GRIPPER）须在 IDLE，只对该组里尚未使能的电机分阶段使能。已使能
  的另一组在此期间按原指令保持（例如机械臂保持着重力下垂补偿后的指令，不会下沉）。分阶段使能前，先让
  该组每个电机应答一次反馈请求；有电机不应答（夹爪未连接/未上电）则整组失败、**一个都不使能**，串口
  `ENABLE: J8 no feedback (not connected or not powered?)`。之后任一电机使能失败，则本次已使能的电机全部
  回滚失能，不留半组。所以夹爪不在时“全部使能”会失败，请用“使能机械臂”。
- **失能**：DISABLE_ARM 只失能 J1–J7，运行中的控制模式（包括 movej/movep）随之结束、回到 IDLE，夹爪保持；
  DISABLE_GRIPPER 只失能 J8（夹持物会松开），机械臂继续当前模式。DISABLE 两组都失能。任何失能都会中止
  正在进行的使能序列。“失能机械臂”结束 move 时不会连带失能夹爪；move 自身失败（超时、掉线等）和 PC
  断线不再失能，而是受控停止（见“受控停止”）。
- **夹爪指令**（命令 27 GRIPPER）：位置 + 速度上限 + 力，所有控制模式下都可用，movej/movep 进行中也可以
  （move 只占用机械臂）。力位混合模式下驱动器以不超过速度上限移向目标位置；碰到物体停住后最多以设定的
  “力”推压——“力”就是驱动器帧里的电流上限 i_des（最大相电流的比例 0–1），实际力矩约为它乘以电机峰值
  力矩，可从遥测的 J8 力矩确认。位置是一步给到，速度由驱动器限制。机械臂的数据流（v3/v5/v7）不再驱动 J8：
  其中 J8 的目标、速度上限、力矩比例被忽略（以前只有 RT Joint 的流能动夹爪，笛卡尔和 NRT 模式下夹爪无法
  控制；SDK 的 servej 还会把夹爪目标发成 0）。模式切换时 MCU 只重新锁存机械臂的保持指令；Qt 进入模式时
  也读取已使能夹爪的保持指令，所以夹爪夹紧物体（指令越过实测角度）时切换模式不会松开。
- **慢速回零**只回机械臂 J1–J7（只使能机械臂时也可用），夹爪保持其指令。
- **启动**：上电预检要求 J1–J7 全部在线；J8 不在时打印 `CAN preflight: gripper J8 not found; the arm runs
  without it` 并正常启动（以前 8 个电机缺一个就停在预检）。CAN FD 判据改为“在线的电机都回 FD”。
  换上新夹爪（同为 ID 8 的达妙电机）后，需在全部失能时重新“应用电机模式”，把它设为力位混合。
- **Qt**：机械臂页“② 全部使能 / 使能机械臂 / 使能夹爪 / 全部失能/停止 / 失能机械臂 / 失能夹爪”。
  夹爪使能失败只失能夹爪这一组，不影响已使能的机械臂。底部状态栏显示“使能=机械臂+夹爪/机械臂/夹爪/无”。
  关节表的“M8 夹爪”一行是夹爪位置（滑条/输入框，0–5.94 rad），其下“夹爪速度”（0.01–10 rad/s）和“夹爪力”
  （0.01–1，步长 0.01）两行各有滑条和输入框；夹爪使能后在任何模式下可用，拖动时最多每 20 ms 发一次指令，
  使能夹爪时把这里的速度和力按它当前位置应用一次。速度、力可在使能前预先设置。
- **力矩显示**：关节表每个电机在“实际位置”条之后有“实际力矩 (N·m)”条和数值（含夹爪 M8），来自遥测的
  实测力矩（关节坐标，带符号）。条以 0 为中线，正值向右、负值向左；满量程为电机峰值力矩但不超过驱动器的
  力矩反馈范围：J1/J2 ±40（DM-J8009P，额定 20）、J3/J4 ±28（DM-J4340P-2EC V1.1 峰值 40，反馈范围
  TMAX 28，额定 12）、J5–J8 ±10（DM-J4310-2EC 峰值 12.5，反馈范围 10，额定 3.5），虚线为额定力矩。
  超过额定变橙色，超过满量程 90% 变红色。约 30 Hz 刷新，显示两次刷新之间 1 kHz 采样的平均值（驱动器
  基于电流估算的力矩噪声较大）。
- **SDK**：`infrabot::Robot::servo_on(MotorGroup::Arm | Gripper | All, error)` 与 `servo_off(...)`，等待
  遥测确认；原 `servo_on(error)`/`servo_off(error)` 即 `All`。`gripper(position, speed, force, error)`
  发夹爪指令，MCU 执行后返回。

模式切换锁存保持指令（机械臂 J1–J7；夹爪保持其指令）：使能状态下指令与实测相差 ≤ 0.1 rad 时保留原指令（静止时实测比指令低一个
重力下垂量，重新锁存实测会让机械臂往下掉一块），相差更大（如关节被挡住）才锁存实测角度。
movej/movep 同样从当前指令起步。Qt 进入 RT/NRT 模式时用 GET_HOLD_POSITION 读取保持指令作为
初始目标；旧固件不支持时退回实测角度。

RT/NRT Cartesian 共用 `ArmCartesianTracker`（`arm_motion.c`），末端走直线：

1. 直线参考：参考位姿以笛卡尔限速/限加速度、带刹车的方式朝目标移动——位置沿直线、
   姿态绕固定轴转（位置与姿态合成一个 6 维向量，同时起停）。速度上限见下方“笛卡尔速度接口”。
2. IK：每周期从**当前关节指令**做一次完整高斯-牛顿 QP 迭代（同 infrabot_ik 模型与权重，步长 1.0）
   追参考位姿；参考在动时每周期必走一步，静止时仅在误差超过容差时才走（肘部不会自己动）。
   零空间（肘部）朝中立位每次迭代最多 2e-5 rad，移动中缓慢回中，而不是一开始猛甩。
3. 关节限速与公共时间缩放：每个关节的速度上限 = min(3.14 rad/s, 由笛卡尔上限导出值, 电机额定转速,
   限位刹车曲线 √(2a·到限位距离))。本周期所有关节步长乘同一个系数使任何关节不超限——末端仍在直线上，
   整条线一起减速；关节接近 URDF 限位时整条线提前减速，停在限位前而不是被硬截停。
4. 关节加速度上限（由笛卡尔加速度导出，留 3 倍余量）作最后保护，正常运动不触发。
5. 残差调速：IK 残差超过 0.2 mm（上限的 40%）后参考开始减速，在 0.5 mm/0.01 rad 处降到 2 mm/s 爬行，
   于是在可达边缘、奇异附近都是慢慢靠近，而不是高速撞上。

电机额定转速（达妙说明书，`app_config.h`）：J1/J2 DM-J8009P 100 rpm = 10.47 rad/s，J3/J4 DM-J4340P
36 rpm = 3.77 rad/s，J5–J7 DM-J4310 120 rpm = 12.57 rad/s（24 V 空载分别 160/52/200 rpm）。
当前另外统一施加 J1–J7 的 3.14 rad/s 控制上限，低于这些额定转速。任何一轴触顶，整条路径自动降速。

笛卡尔速度接口：RT 每个 DMCP v7 包、movep 每条命令都带 `cartesian_limits`（uint16：线速度 mm/s、
角速度 mrad/s、线加速度 mm/s²、角加速度 mrad/s²；0 = 默认）。默认 500 mm/s、180°/s、2000 mm/s²、
360°/s²，上限与默认相同（实机调定：500 mm/s、3142 mrad/s、2000 mm/s²、6283 mrad/s²；1.5 m/s、5 m/s²
抖动明显），超出则 RT 包被拒
（reason=7）、movep 返回 INVALID。关节限速按 0.2 m/rad、0.6 rad/rad 由笛卡尔上限导出（最大 5.24 rad/s），
再受上面的额定转速限制。参考 Flexiv RDK 的 `NrtCartesianCmd`（max_linear_vel/max_angular_vel/
max_linear_acc/max_angular_acc，默认 0.5 m/s、1 rad/s、2 m/s²、5 rad/s²）与 franky 的“机器人硬上限 +
用户设定”分层（FR3 硬上限 1.7 m/s、2.5 rad/s）。RT 中途调低速度时，生效值按加速度上限平滑下降，
调高立即生效。movep 报文里的逐关节速度/加速度只限制对应关节（不再按比例压低笛卡尔速度）；
Qt 发送 MCU 允许的最大值，即只用 MCU 自己的导出值和额定转速。
Qt 在笛卡尔区“笛卡尔速度上限”中设置，任何模式下可改，RT 下一包即生效。

加速度为什么不能再高（按 URDF 做逆动力学 RNEA 估算）：URDF 质量偏小——在日志的
IDLE 位姿上实测 J2/J4 保持力矩 3.28/4.00 N·m，URDF 只有 1.49/1.21 N·m，故按 2 倍质量评估。
- 力矩不是瓶颈：5 m/s² 时最大总力矩约为额定的 59%（10 m/s² 约 85%）。
- 限制在 MIT 位置 PD：目前不发力矩前馈，加速所需力矩全靠位置误差产生，滞后与加速度成正比；
  J1/J2 的 PD（Kp 300、Kd 2.5）阻尼比约 0.17–0.24，加速起止会以约 6–9 Hz 回弹。2 倍质量下 5 m/s²
  的滞后约 3.6 mm（中位）/7 mm（95%），含回弹峰值约 11 mm；2 m/s² 时约为其 40%。
因为与加速度成正比，可直接以 2 m/s² 下的实测表现按比例估计其它值。实机验证：5 m/s² 抖动明显，
2 m/s² 合理（即上限）。降低回弹：J1/J2 的 Kd 调大（MCU 允许 ≤ 5，Kd 5 时阻尼比约翻倍）。
要在不抖的前提下提高加速度，需要加加速度限制（S 曲线，franky 的做法）和基于辨识后质量参数的
重力/惯量力矩前馈。

线、角两组上限各自生效：参考在 6 维空间里沿一个方向运动，该方向上允许的加速度取“线分量不超线加速度、
角分量不超角加速度”中较紧者。纯平移只受线加速度限制，纯旋转只受角加速度限制。（修正前两者共用一个
标量：速度比例 0.5 m/s : 180°/s 与加速度比例 2 m/s² : 360°/s² 不一致时，纯平移只有 1 m/s²。）
movep 报文里的逐关节加速度上限同时按 0.2 m/rad、0.6 rad/rad 收紧末端加速度，否则关节被加速度上限拖住、
单独滞后，IK 残差超限而阻塞。

位置速度（POS_VEL）配置下的跟随：驱动器自己做位置环，帧里只有目标位置 p_des 和限速 v_des，
没有速度前馈。实测关节以一阶滞后跟随 p_des，时间常数 = 减速比 / KP_APR（寄存器 27；位置环把输出轴角度
误差乘 KP_APR 当成**转子**速度指令）。模板 KP_APR = 54：J1/J2（9:1）0.17 s，J3/J4（40:1）0.74 s，
J5–J7（10:1）0.19 s。证据：慢速回零 0.1 rad/s 时 J2/J4/J7 落后 17/73/18 mrad，正好等于 9/40/10 × 0.1/54
（ACC/DEC 从 2 改到 50 后仍然一样慢，所以不是加减速限制）。于是关节以 v 运动就落后 τ·v（J4 在
0.5 rad/s 时落后 0.37 rad）。

MCU 的处理（`ArmDriveLead`，`app_tasks.c` 1 kHz 发送前，所有模式：RT/NRT 关节、RT/NRT 笛卡尔、IDLE）：
- 发给位置速度驱动器的目标 = 指令 + τ·指令速度。RT 笛卡尔、movej、movep 用规划器自己的指令速度；
  RT 关节用最近 10 ms 的平均（减小离散目标更新的速度脉冲；一步跳变超过
  2·v_des·1 ms 视为重锁存，不超前）。τ 用减速比 / KP_APR：应用位置速度电机模式时 MCU 逐个读 J1–J7 的
  KP_APR（串口打印 `ARM_MODE: position-velocity KP_APR=54,54,...`，不应答的电机标 `(no reply)` 并沿用
  54），之后通过“读寄存器/写寄存器/写入内置Flash默认模板”读写寄存器 27 时也会更新。
- 超前的目标允许越过 URDF 限位（关节本身跟随不越限的指令）。最初把目标截在限位上：J2/J4 下限正好是 0
  （回零姿态），往下/往回运动时超前量被截掉，实测 J4 落后 207–228 mrad、末端比指令高 20–56 mm
  （仿真复现：从 z≈434 mm 降到 250 mm，J4 落后 268 mrad、偏 78 mm；不截断：7 mrad、1.8 mm）。
  安全保护改为：关节**实测**已到达或越过限位时，不再往外超前，所以驱动器比模型快时也停在限位上
  （仿真：驱动器快 20%、全速冲向回零姿态以下的目标，越限 < 1 mrad；只超前不保护则越限 120 mrad）。
- 仿真（上述实测模型，500 mm/s）：Z+/X+ 150 mm、从高处降到 250 mm、X 往回 240 mm，末端与指令偏差
  0.2–0.4 mm，与指令同时到位；不补偿则最大落后约 0.4 rad、3.3–3.5 s 才到位。
  模型偏差的影响：τ 偏 10% 时偏差约 10–15 mm（快则冲过、慢则落后），偏 20% 时约 20–35 mm。
- 取消跟随误差调速（原先落后 0.03 rad 就减速，正常运动也一直被压到约 30 mm/s），位置速度关节也不再做
  0.25 rad 不跟随检查（只对 MIT 关节保留，触发时受控停止）：保护不能影响正常运动。驱动器掉线改由“反馈超时”检测：
  RT 笛卡尔中任一关节 150 ms 无反馈即受控停止（`RT_CARTESIAN STOP: Jn no feedback for .. ms`），
  与 movep 的反馈过期判定相同；movep 本身已有该检测。
- 位置速度关节限速仍为 v_des 的 90%（`ARM_POSVEL_SPEED_FRACTION`），超过则整条直线减速。

验证补偿：慢速回零时 `MOT` 行 `err_mrad` 应接近 0（实测已为 0，未补偿时 J4 约 −73）；RT 笛卡尔 `RTIK`
行 `lag=Jn:..` 为本秒偏离指令最大的关节（mrad），`cmd`/`meas` 应相差几毫米以内。若机械臂停下时明显冲过
目标再退回，说明驱动器比模型快（KP_APR 实际更高，或 τ 估计偏大），请读回 KP_APR 核对。
J3/J4 的 0.74 s 时间常数本身太慢：补偿误差、停止时的收尾都按它放大。可在驱动器上把 J3/J4 的 KP_APR
逐步调高（如 54 → 100 → 150，观察有无振荡/啸叫），MCU 会按新值自动调整补偿。
ACC/DEC 保持 50/−50（`infrabot.tsv`）。它不是位置速度模式慢的原因（2 → 50 前后滞后不变），也不决定
运动有多快：它只是驱动器自己加减速的上限，实际加速度由轨迹规划决定（笛卡尔和 movej 由 MCU 规划，
RT 关节由发送方规划，并受 3.14 rad/s 位置变化上限约束）。超前补偿假设驱动器不被它限制：若它按输出轴 rad/s² 生效（手册写 Krad/s²，实际单位
未验证），仿真中改回 2 会让 RT 关节 0.5 rad/s 停止时过冲 36–70 mrad、笛卡尔偏差数十毫米；50 时与不限制相同。
手册也建议出现振荡时调大 ACC/DEC。只有目标直接跳变的单电机“发送位置/速度”会用满这个上限（起步较猛）。

MCU 只接受发给自己 IP 的指令：发到指令端口的广播/组播直接丢弃（局域网路由器 192.168.0.1 每约 10 s
向 255.255.255.255:5001 广播 380 字节，过去显示为 `CMD_INVALID(reason=1,detail=380)`）。

不可达目标：QP 失败或残差超过 0.5 mm/0.01 rad 时视为“阻塞”：所有关节按同一比例、在加速度上限内刹停
（接近限位的关节更急），参考跟随机械臂实际位姿/速度；之后保持不动，直到目标变化超过 0.05 mm/0.5 mrad
才再尝试（不会沿边缘慢慢滑）。Qt 只发送主机 IK 判定可达（残差 ≤ 0.5 mm、0.01 rad）的目标，超出时
提示“目标超出可达范围，未发送”，MCU 保持上一个可达目标。已知限制：若别的客户端把机械臂推到伸直的
可达边缘（越过最大伸展点），沿直线退回可能让 J4 顶到上限而再次阻塞——此时用 RT/NRT Joint 退回。
CAN 故障时失能；任一关节 150 ms 无反馈、或 MIT 关节实测与指令偏差 > 0.25 rad 时受控停止，偏差大的关节停在
实测位置、不再往前推（位置速度关节不做偏差检查，见上）。movep 到位判断使用实测位姿。

修正：MCU IK 在达到迭代上限时原先报告的是最后一步之前的残差（主机 infrabot_ik 报告最后一步之后的）。
跟踪器用残差判断能否跟随，这使速度超过约 0.4 m/s 时误判为“跟不上”而顿挫偏离；现已与主机一致。

为什么之前不走直线：旧做法把 IK 直接解到最终目标，再让每个关节各自限速/限加速度地跟过去，
关节空间插补在笛卡尔空间是曲线（离线仿真 50 mm 阶跃偏离直线约 10 mm，100 mm/s 拖动约 3 mm，
肘部偏离中立位时约 7 mm）。现在离线仿真：默认速度 50–80 mm 移动偏离 ≤ 0.005 mm；1.5 m/s、180°/s
设定下 200–300 mm 移动偏离 ≤ 0.01 mm、纯旋转 90° 末端移动 0.01 mm，关节不超额定转速；高速冲向不可达
目标时在边缘停下，偏离直线 3–11 mm，无关节撞限位。重力下垂随位姿变化对直线度的影响按 URDF 质量估算约 0.14 mm/50 mm，
可忽略；但绝对位置仍有固定的下垂偏差（与 RT_JOINT 相同，取决于 Kp）。

串口日志（`app_tasks.c` 状态任务，1 s 周期）：

| 行 | 何时输出 | 内容 |
|---|---|---|
| `STAT` | 使能时每秒；失能时每 5 s；任一错误计数非零时立即 | 控制器状态、使能位、控制频率/漏拍/最大周期、CAN 收发帧数、UDP 指令数/间隔/抖动（RT 关节与笛卡尔流都计入）、遥测数；`CAN_TX_ERR`/`CMD_INVALID`/`TEL_ERR`/`UART_DROP` 仅非零时出现。`CMD_INVALID=n(reason=r,detail=d)` 给出本秒最后一个被拒包的原因：1 格式不符（d=包长）、2 关节流不在使能的 RT_JOINT、3 当前状态不允许使能/设零、4 movej/movep 占用中、5 未知命令、6 笛卡尔流不在使能的 RT_CARTESIAN、7 笛卡尔速度超上限、8 维护参数无效、9 不支持定时执行；其余 d=命令码 |
| `MOT` | 使能时每 5 s；否则每 30 s | 关节坐标位置 `q_mrad`、跟踪误差 `err_mrad`（指令−实测：重力下垂/滞后）、力矩、MOS 温度、状态码 |
| `MOTOR` | 电机进入/离开故障码时 | 例 `MOTOR DM8009P-2 state 1->A OVERCURRENT`（8 过压 9 欠压 A 过流 B MOS 过温 C 线圈过温 D 通信丢失 E 过载） |
| `CAN` | 错误计数/被动/警告/离线/中断状态变化，或出现新的协议错误时 | TEC/REC、错误状态、LEC/DLEC、错误中断 |
| `RTIK` | RT_CARTESIAN 中每秒 | 本秒各 IK 状态次数 n[0..6]、耗时 last/max µs、生效的速度上限 `vmax`（mm/s、°/s）、时间缩放 `scale`（<100 表示被关节限速：额定转速或限位刹车）、`blk=1` 表示目标不可跟随而保持（超出可达范围/奇异）、`lag=Jn:x` 本秒偏离指令最大的关节及偏差（mrad，含重力下垂/驱动器滞后）、目标/指令/实测末端坐标 `tgt`/`cmd`/`meas`（mm）：`cmd` 是否走直线看规划，`cmd`−`meas` 是下垂/滞后 |

| `RT_CARTESIAN STOP` | RT 笛卡尔因故障自动停止时（随后受控停止；CAN 故障时失能） | 原因：CAN 故障、某关节 150 ms 无反馈（`no feedback`）、MIT 关节实测与指令偏差超过 0.25 rad（`not following`）、或 IK 输入无效/数值失败 |

| `ARM_MODE` | 应用位置速度电机模式时 | 读回的 J1–J7 KP_APR（决定位置速度补偿），`(no reply)` 表示该电机未应答、沿用 54 |
| `SELFCHECK:` | 应用电机模式时 | 参数自检结果：`OK, 8 drives`，或每处不符/无应答一行，见“参数自检” |

| `ETH: health` | 每 60 s；以太网错误计数增加时（最多每秒一次） | 链路、收发包、错误 |

启动、使能、模式切换、链路变化等事件日志保持不变。

遥测的 `mode` 字节（v2 的 `reserved[2]`）：

- bit7：支持分层模式协议。
- bit6：本次启动已经完成电机配置提交。
- bit5..4：J1–J7 电机配置，0=混合/无效，1=MIT，2=位置速度；J8 必须力位模式。
- bit3..0：实际执行模式。

配置提交沿用现有逐台 CAN 写入实现（部分电机固件不返回写入后的回读帧）；写完后由参数自检逐台读回
CTRL_MODE 等寄存器，全部相符才置“已应用”（见“参数自检”）。
任一提交失败或修改单电机 CTRL_MODE 会清除整臂配置就绪标志；使能路径不再改写 CTRL_MODE。
每次 MCU 启动都从失能 IDLE 开始，必须重新应用电机模式；已保存的增益等控制参数仍保留，
运行态和使能态不保存、不自动恢复。应用电机模式不隐式保存电机 Flash。

RT 关节包仅在 RT_JOINT 接受；DMCP v7 笛卡尔包（284 字节）仅在 RT_CARTESIAN 接受；DMOV 的 MOVEJ/MOVEP
分别仅在 NRT_JOINT/NRT_CARTESIAN 且满足原有安全检查时执行。
IDLE 不接受单电机运动维护指令；单电机运动接口也须处于 RT_JOINT 且匹配所选电机配置。
切换/失能清理旧队列，NRT 会话释放后不能用旧 ID 重新激活。

## 协议头文件

所有 UDP 报文（DMCP v2/v3/v4/v5/v7、DMAR、DMTL v2/v3、DMIF/DMIO、DMCS/DMCR、DMOV/DMOS）、命令码、
状态码、停止原因和达妙寄存器表定义在 `protocol/infrabot/protocol.h`（C11 / C++17 通用），固件里的
`DM_ETH_CMD_*`、`DM_ETH_MODE_*`、`DM_ETH_CONTROL_*`、`DM_ETH_INVALID_*` 等都是它的别名，结构尺寸由静态
断言锁定。

固件和 PC 端（InfraBot SDK）是两个互不依赖的仓库：SDK 的 `include/infrabot/protocol.h` 是同一个文件的
另一份拷贝，两份内容完全相同。改协议时改一份、复制到另一份（`cmp` 可核对）。运行时 DMIO 能力位和
各报文的版本、长度检查能识别对方是旧版本。固件的构建和主机测试只用本仓库的文件。

寄存器表（`INFRABOT_REGISTERS`）给出每个寄存器的类型（u32/f32）、读写属性和写入范围：只读、可写
（全部失能时经 WRITE_REGISTER 写入）、受保护（MST_ID、ESC_ID、can_br：驱动器可写但 MCU 拒绝，在线修改会
破坏 CAN 寻址或反馈解码）。MCU 的 WRITE_REGISTER 和 PC 的模板导入都按它检查，范围与以前固件里的
`write_allowed` 相同。

## 遥测 v3

DMTL v3 共 348 字节、1 kHz，DMIO 能力位 0x80（`INFRABOT_CAP_TELEMETRY_V3`）。前 180 字节与 v2 相同
（version=3），只读头部的旧程序按 magic 识别即可：

| 部分 | 字节 | 内容 |
|---|---|---|
| head | 180 | 序号、时间戳、8 个电机的实测位置/速度/力矩/状态码/MOS 温度/反馈计数，指令序号，`status`（使能、零点、控制器状态）、`enabled_mask`、`mode` |
| command[8] | 8×16 | MCU 本拍发给各电机的指令（关节坐标）：规划位置（位置速度关节为超前补偿之前的值）；速度项（MIT 为速度前馈，位置速度/力位为 v_des）；MIT 力矩前馈（其它模式为 0）；线圈温度；标志：使能、被维护命令或 move 占用、被 v4 STOP 保持、力矩达到监督限值、已使能但反馈超过 50 ms 未更新；驱动模式 |
| link | 20 | MCU 侧上一秒的链路统计（每秒更新一次）：接收的指令包数、被拒包数、最大间隔 µs、最大抖动 µs、控制环漏拍、最大控制周期 µs、CAN 发送错误、遥测发送错误、最后一个被拒包的原因（本秒没有被拒包时为 0）；超过 65535 饱和 |
| safety | 20 | 受控停止：原因、阶段、关节、细节、无 PC 时距失能的剩余毫秒；参数自检：结果、第一处失败的关节和寄存器、读回值与期望值（寄存器原始位） |

以太网发送是阻塞式的，pbuf 发完即释放，lwIP 16 KB 堆同一时刻只占一个遥测包（约 420 字节），带宽约 3.3 Mbit/s。

## 参数自检

“应用电机模式”（SET_ARM_MODE）写完 CTRL_MODE（位置速度模式再读完 KP_APR）后，逐台读回 MST_ID、ESC_ID、
CTRL_MODE、PMAX、VMAX、TMAX，与固件表（`dm_motors[]`：MIT 编码和遥测换算正是用它）比对：反馈 ID、CAN ID、
本次选择的模式（J8 为力位）、位置/速度/力矩映射范围（浮点相对误差 1e-3）。J1–J7 必查，J8 只在开机后
应答过（已连接）时查。每次读回最多等 `DM_SELFCHECK_READ_TIMEOUT_MS`（20 ms），无应答算失败。DMIO 能力位
0x200（`INFRABOT_CAP_SELFCHECK`）。

- **全部相符**：配置就绪，DMAR status 0、value = 模式（与以前相同），串口
  `SELFCHECK: OK, 8 drives: MST_ID, ESC_ID, CTRL_MODE, PMAX/VMAX/TMAX as configured`。正常约 200 ms 完成
  （PC 端最多等 3 s）。
- **有不符或无应答**：配置**不就绪，不能使能**。DMAR status 6（MISMATCH），value = 关节 | 寄存器 << 8 |
  结果 << 16（结果 2 不符、3 无应答，关节从 0 计），报告第一处；串口每处一行，例如
  `SELFCHECK: J3 VMAX read 8.000 expected 10.000`、`SELFCHECK: J5 TMAX no reply expected 10.000`，最后
  `SELFCHECK: n mismatch(es): motor profile not ready, enable refused; ...`；遥测 safety 的 selfcheck 字段同样给出
  第一处的关节、寄存器、读回值和期望值。
- **处理**：用电机参数模板（SDK 的 `config/infrabot.tsv`）重写该电机的参数，或改正固件表（`app_state.c` 的
  `dm_motor_position_max/velocity_max/torque_max`），再重新应用电机模式。这样换电机、换夹爪后不会出现
  openarm_can 出过的问题：某型号 VMAX 表值写错，速度被静默按比例缩放，直到有人读寄存器才发现。

## 受控停止

以前的停止条件（PC 断流、movej/movep 失败或取消、RT 笛卡尔故障）都会直接失能，承重的机械臂随即下坠。
现在 MCU 做受控停止（`app_safety.c`，DMIO 能力位 0x100 `INFRABOT_CAP_CONTROLLED_STOP`），**并且从不自行失能**：
外部控制模式下关掉 GUI、拔网线、move 结束后 PC 离开，机械臂都刹停并保持使能。
撤去力矩需要 PC 明确发 DISABLE 或操作者点击 LCD 首页 `DISABLE ARM`。
LCD 本地保持及 `GRAVITY_FREE/LOCK` 不依赖 PC 心跳；切回外部 RT/NRT 模式恢复原有通信看门狗。

1. **离开控制模式**：立即回到 IDLE（RT 流和 movej/movep 不再被接受，还在发流的程序会被明确拒收）；进行中的
   movej/movep 结束（失败原因照常在 DMOS 里锁存，直到 PC 取消、切换模式或失能），RT 笛卡尔跟踪器复位。
   被打断的模式记在遥测 safety 的 `stop_mode` 里，供 PC 一键恢复（见第 4 条）。
2. **刹停**（BRAKING）：J1–J7 的指令在关节空间按同一比例减速到静止。起始速度取最近 10 ms 指令的平均速度，
   共同停止时间 T = 最快关节速度 / `DM_STOP_DECELERATION_RAD_S2`（8 rad/s²），最多 `DM_STOP_MAX_BRAKE_S`
   （0.5 s）：各关节同时停下，关节空间方向不变；指令不会比开始时更越过 URDF 限位。MIT 速度前馈随之减到 0，
   力矩前馈保持原值；位置速度关节的超前补偿用刹车速度。被卡住的关节（NOT_FOLLOWING、TORQUE_LIMIT 的那个
   关节）直接把指令改成实测位置，不再往前推。夹爪和被 v4 STOP 保持的电机不动。
3. **保持**：刹停后若 PC 在（100 ms 内有心跳或任何被接受的命令），就是正常的 IDLE 保持；否则进入 HOLDING：
   保持使能，没有时间限制，PC 多久不回来都一直保持。PC 回来（例如 Qt 重启后重新连接、网线插回后心跳恢复）
   → 正常 IDLE 保持。
4. **确认与恢复**：停止原因 `stop_reason` 和被打断的模式 `stop_mode` 锁存在遥测里，直到 PC 确认：
   - 刹停结束（阶段 NONE）后成功切换模式。**恢复**就是重新进入 `stop_mode`，从停下的位置继续：MCU 从
     保持指令起步，RT 模式的流从这里开始，movej/movep 重建会话并先保持在这里。
   - 停止发生在 IDLE（`stop_mode` 为 IDLE）时，在 IDLE 中再发一次 SET_CONTROL_MODE IDLE 即确认；
     刹车中这样发不算确认。
   - 使能也会清除。
   前一次停止还没确认时又发生的停止（此时已在 IDLE），保留最早记下的 `stop_mode`。切换模式要求
   J1–J7 速度都 ≤ 0.05 rad/s：刚停下时位置速度驱动器还在跟随停住的指令（J3/J4 约 0.74 s），MIT 关节
   也会小幅回弹，这时切换会回“忙”（status 4）；PC 的恢复（SDK `resume()`、GUI“恢复”按钮）会等机械臂
   静止后再切，回“忙”就重试，最多 3 s。DMIO 能力位 0x400（`INFRABOT_CAP_RESUME`）表示支持。
   DISABLE 仍立即失能，进行中的停止随之结束。刹停或无 PC 保持期间控制器状态为 STOPPING（10）。

LCD 首页 `HOME` 提供 `ENABLE ARM / DISABLE ARM / STOP / RESUME`，请求由 1 kHz 控制任务处理。
使能在模式未就绪时先配置 MIT 并完成同一套自检，只使能 J1–J7。STOP 取消待执行的使能，
包括同一拍排队的 PC 使能；若分步使能已开始，则取消剩余步骤，已上电的关节保持使能。
RESUME 在反馈新鲜、静止、无硬件/限位故障时确认停止；恢复先前的本地重力模式，或进入 IDLE
等待新的 PC 运动。它不重放外部轨迹，也不绕过重力模式停止后的增益恢复阶段。
`GRAVITY` 页滑条调节统一的 Kd 和 Lock Kp，限速生效，仅保存于 RAM，详见 README。本地重力补偿
不做摩擦补偿（只补重力、offset、spring·q）。FREE/LOCK 与 RT/NRT 指令使用同一个 3.14 rad/s 每轴上限：
从 50% 开始平滑增加有限的反向制动力矩，达到或略超过上限继续保持重力模式，页面显示制动关节；
朝关节限位运动过快（大于按 5 rad/s² 来得及停下的速度）时提前制动。只有超过 125% 的独立异常阈值
才触发 `GRAV_STOP check=SPEED`；其他位置、力矩、反馈、温度保护和模式切换静止条件继续生效。
手拖时这是基于实测速度的力矩反馈调节，有限力矩不能保证瞬时严格钳制速度。

长时间无人保持时，重力负载的电流一直在流，电机会发热；驱动器自身的过温保护是最后一道防线（触发后该
关节报 DRIVE_FAULT，其余关节继续保持）。

MCU 只在下面几种情况下断电，`tests/run_host_tests.sh` 的 `test_no_self_disable` 会核对代码里所有能断电的
地方都属于这几类：

- PC 明确请求：DMCP v3 DISABLE、分组失能（DISABLE_ARM/GRIPPER）、v4 DISABLE、设零前的失能；
- LCD 操作者明确点击 `DISABLE ARM`：仅失能 J1–J7，保留 J8；
- 使能序列失败时，回滚本次正在使能的那一组（它们使能前本来就是失能的）；
- 上电初始化；
- 手动读 RID 10（CTRL_MODE）发现某驱动器的实际模式与 MCU 下发的不一致：继续发帧会被驱动器按错误的模式
  解释，保持不住，只能失能。

| 原因（`INFRABOT_STOP_*`） | 条件 |
|---|---|
| 1 STREAM_LOST | RT 流或 IDLE 心跳 100 ms 未到（原来直接失能） |
| 2 MOVE_LOST | movej/movep 的 100 Hz 保活中断 |
| 3 MOVE_FAILED | movej/movep 失败（总超时、IK 无效、CAN 发送失败等），细节为 DMOS 原因码 |
| 4 REQUESTED | PC 要求：DMCP v3 STOP（命令 5，任何来源都可发，重复发送不重启刹车）、DMOV CANCEL、move 进行中的 v4 STOP |
| 5 NOT_FOLLOWING | 关节落后指令超过 0.25 rad（RT 笛卡尔的 MIT 关节、movep），该关节停在实测位置 |
| 6 INVALID_TARGET | RT 笛卡尔目标被 IK 拒绝（输入无效/数值失败），细节为 IK 状态 |
| 7 FEEDBACK_LOST | 已使能的机械臂电机反馈超过 `DM_STOP_FEEDBACK_LOST_MS`（150 ms）未更新，任何模式 |
| 8 DRIVE_FAULT | 已使能的机械臂电机报故障码（关节 + 细节为状态码 8–E），任何模式；或 RT 笛卡尔下 CAN 控制器报错（无关节，细节 0） |
| 9 TORQUE_LIMIT | 已使能的机械臂电机实测力矩 ≥ `DM_ARM_TORQUE_LIMIT_NM` 连续 `DM_TORQUE_LIMIT_MS`（100 ms），该关节停在实测位置 |

CAN 控制器报错以前是立即失能。现在也是受控停止：这个错误标志在任何一次 CAN 协议错误后置位并一直保持到
重启，一次总线干扰就让机械臂掉下来不合理；总线真的坏了时 DISABLE 帧也发不到驱动器。

细节字段只对 MOVE_FAILED（DMOS 原因）、DRIVE_FAULT（驱动器状态码）和 INVALID_TARGET（IK 状态）有意义，
其余为 0。故障码和反馈丢失只在出现时触发一次；力矩超限若一直被推
则每 100 ms 再触发一次（关节顺着推力让开）。遥测指令块的 `TORQUE_LIMIT` 标志实时显示超限关节。

力矩监督限值 {36, 36, 25, 25, 9, 9, 9} N·m 是 0.9 × min(峰值力矩, TMAX)（J8009P 峰值 40；J4340P 峰值 40、
TMAX 28；J4310 峰值 12.5、TMAX 10）。夹爪会有意堵转夹持，不监督。

**IDLE 也受看门狗监视**：使能后的 IDLE，以及模式切换回的 IDLE，PC 发 100 Hz 心跳（DMCP v3 命令 21，
Qt 一直在发）表示 PC 在线；心跳中断即 STREAM_LOST，机械臂已静止，只是状态变为无 PC 保持（STOPPING）。
只靠 RT 流或 DMOV 保活、不发心跳的客户端，停止后机械臂同样一直保持使能。

**遥测端点接管**：控制期间同一 IP 的重新注册允许（重启的 Qt 能在保持期内拿回遥测、恢复心跳）；控制权
所有者 500 ms 无消息后，其他来源也可以注册遥测和接管控制。

串口日志：

| 日志 | 含义 |
|---|---|
| `STOP: <原因> J<n> detail=<d> braking` | 触发，开始刹停（无关节时省略 `J<n>`） |
| `STOP: <原因> ... stopped, IDLE hold` | 刹停结束，PC 在线，正常 IDLE 保持 |
| `STOP: holding, no PC (stays enabled)` | 刹停结束，无 PC，保持使能 |
| `STOP: PC back after <n> s, IDLE hold` | 无 PC 保持了 n 秒后 PC 回来 |
| `RT_CARTESIAN STOP: CAN fault irq=... code=...` + `STOP: drive fault detail=0 braking` | CAN 控制器报错，刹停保持 |

调参（都在 `app_config.h`）：减速度 `DM_STOP_DECELERATION_RAD_S2`、刹车时间上限 `DM_STOP_MAX_BRAKE_S`、
反馈丢失 `DM_STOP_FEEDBACK_LOST_MS`、力矩限值 `DM_ARM_TORQUE_LIMIT_NM` 与持续时间 `DM_TORQUE_LIMIT_MS`。
减速度越大刹得越急，起停冲击也越大。

## 兼容性与验证

必须同时升级 MCU 与 Qt。新 Qt 对不带模式能力位的旧 MCU 禁止使能。
请用配套 SDK 完成驱动配置和 IDLE 使能，再显式切换所需控制模式。同一控制板由一个客户端持有运动控制权。

固件离线测试（不连接真实电机，模拟 CAN 电机，不需要 HAL/网络/RTOS）：

```sh
tests/run_host_tests.sh                          # 全部
tests/run_host_tests.sh test_safety test_selfcheck   # 指定
```

只用本仓库的文件。覆盖：轨迹/IK/跟踪器（`test_arm_motion`）、DMOV 会话及其失败/取消转受控停止
（`test_app_motion`）、控制模式切换与停止确认（`test_control_mode`）、分组使能与夹爪指令（`test_enable`）、
受控停止的刹车、无 PC 长时间保持（模拟 10 分钟不失能）、PC 回来与各监督（`test_safety`）、参数自检
（`test_selfcheck`），以及“MCU 不自行失能”的代码核对（`test_no_self_disable`）。

PC 端的运动会话、SDK 与 Qt 回环测试在配套 SDK 仓库中由 CTest 运行。
离线通过不代表负载稳定性或最坏 1 kHz 时序已在实机验证。


## RT Joint 位置目标速度

J1–J7 统一控制/规划速度上限为 **3.14 rad/s**，定义为 `INFRABOT_ARM_MAX_JOINT_VELOCITY`。
RT_JOINT 位置目标每 1 ms 最多变化 0.00314 rad；速度前馈和位置速度模式 v_des 也受此上限约束。
movej 参数超过上限会由 SDK 限制，MCU 验证；RT Cartesian/movep 在任一关节触顶时同步降低整条路径速度。
辨识项目的 `max_command_velocity` 默认和 UI 最大值同步为 3.14，允许配置更低的应用上限。
电机 MIT VMAX 编码范围/自检值和 J8 夹爪配置不变。这是指令上限，非物理转速的瞬时钳制保证。
笛卡尔上限仍为 500 mm/s、约 180°/s，能否跑满取决于姿态/雅可比；接近奇异或关节限位时会降速。
`tests/test_cartesian_speed_cap.c` 使用真实规划器做理想跟踪检查，不代表实机负载性能。
旧轨迹文件不会自动提速；全部 24 V 的当前机械臂，建议先以规划速度 1 rad/s、加速度 2 rad/s²
重新生成并预检，30% 幅值试跑，再根据跟踪、力矩及停止表现逐步调整。
