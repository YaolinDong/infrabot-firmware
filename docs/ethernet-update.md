# H743 网口升级与回滚（可选构建）

本项目的 2 MiB STM32H743、LAN8720A RMII、32 MiB SDRAM。发布使用 **Release**。常规 Debug 也构建 A/B 签名包，调试时应选择与已确认槽位匹配的 ELF 符号；只有显式 StandaloneDebug 才使用旧的单镜像布局。常规网口升级不使用 BOOT0、不更改 option bytes，不依赖 PC 的实时命令流。板端与 SDK 的维护端口默认 UDP **5002**，沿用 Flash 中静态 IP/MASK/GW（无有效配置时沿用编译默认值）。要求正常 bank mapping、软件启动 IWDG。试运行需网络可用、调度器工作、配置启用的 LCD 初始化成功。

## 分区和失败语义

| 范围（含端点） | 用途 |
|---|---|
| 08000000–0801FFFF | 常驻 Bootloader / Ed25519 公钥；SDK 不写 |
| 08020000–080FFFFF | A 槽；向量表 08020400 |
| 08100000–081DFFFF | B 槽；向量表 08100400 |
| 081E0000–081FFFFF | 原有零位、控制配置和 IP；升级程序不擦写 |

每个应用最多 **916416 字节（另留 64 字节签名）**，两份独立链接、分别认证的二进制装入同一个 IFABv002 包。SDK 只选择备用槽地址匹配的镜像。未来程序超出任一槽会在链接/打包时失败，禁止回退成原地覆盖。已有设备升级前的**当前已确认固件**在整个更新中保持原样；不能保证在再次开始下一次升级后还保留更早的第三个版本。

1. SDK 验证整个包和两个目标地址，向正常应用申请屏幕确认，绑定本次请求的端点、随机会话、操作和目标镜像摘要。应用在临界区拒绝使能、进行中的使能/维护/Flash 写入等状态；不隐式失能，不撤掉保持力矩。维护前支撑好机械臂，显式失能、断开电机动力，控制板保持供电。
2. Loader 使用有会话和偏移确认的 UDP 分块传输；重复帧幂等。完整接收至 SDRAM 并验证 Ed25519 签名、SHA-256、长度、地址、向量后，才擦备用槽，写后从 Flash 全量验证。传输断开且不再有进度时，独立看门狗使板子回到原固件。
3. 每个槽的 manifest、generation、tried、confirmed、revoked 位于不同的 **32 字节 Flashword**。先写入尝试标记，再启动候选。断电/复位后，已尝试但未确认的候选不能再次自动启动。读取损坏槽出现 Flash/ECC 访问异常时，Loader 用复位标记跳过该槽，再选择剩余有效槽。
4. 试启动开启硬件 IWDG（名义约 32 秒，实际随 LSI 变化），不喂狗；试运行应用禁止电机任务、控制命令端口和面板操作。只有实际运行到网络任务、达到启动门槛且 SDK 确认本次镜像，Loader 才写确认标记并重启正常应用。试启动挂起、失联、未确认、复位都会回到之前已确认的固件。观察复位行为时脱离会冻结看门狗的调试器。
5. 传输 100% 不是成功。SDK 要求**正式应用**回复预期槽位和镜像标识才返回成功。如果最终确认已发出但之后断网，PC 无法推断板子是否已提交：结果为 **unknown**，重新 probe；上版仍在另一槽，可以显式回退。升级确认只验证上电/网络健康，不验证全部运动功能或长期行为。
6. 确认后若发现回归，可由 SDK 回退；网络完全不可用时，可在有相应接线的板上**仅按住 KEY2，再按 RESET，继续按住 KEY2 至少 3 秒**，选择上一个有效、已确认的槽。同时按键进入 Loader 不授予网络写入权限。没有备用已确认版本时不会假称已回退。

以上是正常 Flash、供电能够恢复、常驻 Loader 完好的故障模型；不承诺在硬件损坏、两槽均被外部擦除、密钥丢失或常驻 Loader 损坏时自动恢复。恢复的是固件，网络升级流程不回写旧参数快照。后续版本若设计不兼容的持久化数据迁移，应另行设计可回退的配置版本。首次替换原单镜像布局属于 SWD 迁移，断电时可能需要 SWD 恢复旧备份。

## 空板首装或 v1 → v2 迁移

这是一次厂内 SWD 操作。支撑机械臂、失能并断开电机动力，保持控制板稳定供电，连接 fireDAP、关闭其他调试器。使用**本地可信构建**中的 factory 镜像；签名保护应用，不能替代 SWD 操作者对 Loader 的信任。仅 v1 迁移使用最后一个标志；新板首装去掉它：

```sh
python3 -B tools/netboot_factory.py \
  --image build/Release/factory-bank1.bin \
  --backup-dir "$HOME/infrabot-flash-backups" --motor-power-off --migrate-v1
```

程序保存并验证 UID、完整 2 MiB 的 `before.bin`、配置区和快照摘要，写入 Loader + 已确认 A、清除旧 B 元数据，并核对配置与应用启动。迁移替换唯一 Loader，断电时不能指望它自动恢复；保留此次备份并联系维护者，恢复时须核对同一块板的 UID 和整片备份。普通升级不替换 Loader。已经是 v2 的板无需再迁移。

## 客户操作与验收

在 SDK 根目录或解压后的 Linux 发布包执行：

```sh
./flash-net --prepare        # 离线用公钥验签，不连板
./flash-net --probe          # 只读，无弹窗
./flash-net                  # 默认 192.168.0.50；可指定 IP
```

新镜像请求显示来源 IP、与 SDK 终端一致的镜像摘要前 8 位及「拒绝升级 / 允许升级」。必须在 60 秒内触摸允许；拒绝、超时、触摸不可用或驱动不在可维护状态时不进入擦写。允许只对这一次请求有效；升级前重新核对失能状态。已安装同一镜像直接返回，无需授权。网口回滚同样需屏幕同意。SWD 是有物理调试权限的独立维护方式，`./flash-swd` 使用相同签名包，无需网线或触摸屏。

先在两种屏板上验证：拒绝和超时后 probe 应仍为原槽；允许后以另一版本实际升级，看到 `Confirmed application is running.`，再 probe 核对槽和镜像标识。随后测试传输中断、试启动未确认回退与断电恢复。主机模拟结果不能代替这些实机验收。SDK 构建交付包：`python3 -B tools/update/package_update.py`。

若首次安装或迁移中断，保留本次备份并联系维护者。恢复时须核对同一块板的 UID 和整片备份。

## 出厂写保护

普通冷启动在打印 `infrabot_firmware start` 前先扫描槽。两个槽都有已确认记录且未撤销时，新 Loader 先对最新一槽计算完整 SHA-256 并校验 Ed25519；成功就启动，损坏才完整验证另一槽。试启动、确认、维护和回退仍走原校验流程。扫描阶段仅开指令缓存，跳应用或进入维护前关闭；不缓存上一次上电的验签结果。仅按住 KEY2 的 3 秒判定不属于普通启动延时。

新 Loader 和应用都安装后，普通上电查看串口：`NETBOOT: slot_scan=...ms images_checked=...` 是 Loader 实测的槽扫描耗时和完整校验次数；`LCD: ... app_first_frame=...ms` 是应用 HAL 开始计时到写完首帧、开启背光。两者都不包含电源开关到 MCU 解除复位的时间。两槽正常且都已确认时前一行预期为 `images_checked=1`。旧 Loader 配新应用没有前一行。

Loader 默认直接用复位 HSI **64 MHz** 验签（CMake 选项 `FW_BOOT_SCAN_PLL_192=OFF`），不启用扫描 PLL。仍保留单槽优先、指令缓存与 512 B 分块 SHA-256；应用时钟仍为 480 MHz。可以在独立构建目录用 `-DFW_BOOT_SCAN_PLL_192=ON` 对照之前的 192 MHz 版本，不要用更早的不同算法 Loader 代替本对照。两版均用同一已确认应用，普通 RESET 后比较 `slot_scan` 和 `images_checked=1`。在本机 A 槽第 7 代（566,580 B）的切换对照中，64 MHz 路径约 0.33 s，192 MHz 快路径约 0.16 s；应用首帧均为 12 ms。这些是该镜像上的观测值，不是每次启动的硬性时限。

只有启用此选项时，普通上电/RESET 才用 HSI 驱动临时 PLL1：64/10 × 60/2 = 192 MHz CPU，AHB /4 = 48 MHz，APB 不超过 48 MHz。不升压、不依赖外部晶振、不改 Flash 等待周期。仅在复位时钟树、LDO 和 Flash 时序符合预期时尝试；锁定或切换超时退回 HSI。校验完成后确认已切回 HSI、停掉 PLL1、恢复寄存器，再处理按键、Flash 标记、维护或跳转。软件复位、看门狗、试启动请求及 KEY2 路径不要求此快时钟。扫描采用 512 B DTCM 栈缓冲按对齐字读取，仍对**相同的全部字节**做 SHA-256 并检查 Ed25519；不把验证结果跨复位缓存。电压和频率限制见 [ST 的 STM32H743 数据手册](https://www.st.com/resource/en/datasheet/stm32h743xi.pdf)。

常规 SDK 升级只更新应用槽。出厂可对 Bank 1 的第 0 扇区设置 WRP，以防调试器误擦常驻 Loader。已部署设备如需更换受保护的 Loader，应安排维护人员通过 SWD 验证板卡身份、备份和现有 Loader，完成更换后复核写保护及应用启动。请勿用整片擦除替代维护流程。
